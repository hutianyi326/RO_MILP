# 罗马尼亚定期取数与额外 API 权限评估

评估日期：2026-09-30。研究基线：2025-01-01—2026-08-31，通用独立储能，P 为参数，比较 2h/4h。本文为主线程的取数方式评估补充，不属于上一轮独立审核覆盖文件，不改变国家状态和阶段批准。F 表示官方说明或已保存的取数事实，I 表示研究判断，A 表示拟议运行条件，U 表示待确认。

## 1. 结论与适用范围

**I：现有公开渠道可以支持日前市场及部分系统数据的低频研究取数试运行，但尚不足以保证所有研究数据长期、完整地自动更新。建议优先申请 ENTSO-E 正式 REST API 权限；同时确认 Transelectrica 的最终偏差价格出口及 OPCOM 日内历史数据渠道。现阶段不建议购买 M7 交易 API。**

“有公开取数地址”“样本请求成功”“连续定期获取通过验收”是三个不同状态。本轮完成的是样本证据和处理核验，未做连续运行、全期覆盖或数据服务稳定性验收。是否需要账号、许可或付费，必须按具体数据服务确认，不能由一次网页失败推断。

对于仅做 DA 价量研究，现有公开导出值得继续验证；对于 DA、IDA、IDCT、容量、激活和偏差结算的联合研究，当前数据缺口仍会阻止完整收益测算。申请接口权限也不能自动解决价格单位、初终版、缺值原因和历史发布时间问题。

## 3. 应申请什么、应向谁确认什么

### 3.1 ENTSO-E：建议优先申请正式数据 API 权限

F：官方说明要求注册并验证 Transparency Platform 账号，向指定邮箱申请 RESTful API access，获批后在账号中生成 security token [S01]。正式生产请求入口是 `https://web-api.tp.entsoe.eu/api` [S02]。这些是官方当前说明，尚未取得本项目账号授权或 RO 数据响应。

I：该权限最有价值的用途是验证原生分技术出力、物理流、相关预测和第二来源 DA 核验；跨境容量及偏差价逐项测试，不承诺全期覆盖。官方发电目录确认分技术实际出力这一数据类别存在 [S04]；各区域、各数据项实施版本仍需按官方 MoP 和路线图核实 [S05]。账号权限不是 RO 数据完整性的证明。

申请准备范围：RO 及相关边界，2025-01-01—2026-08-31 历史样本与后续每日研究更新；说明是数据消费用途。获批后先验证既有七个边界/代表日和一个整月，核区域代码、币种、时间粒度、缺值、版本和单位，再决定扩展。一个接口权限可以承担多个候选数据项，不必按每个数据集分别申请一个 token；具体可访问范围仍以账号权限为准。

F：官方 2026-04-20 更新说明列出每个账号/token 每分钟 400 个请求的主要限制 [S03]。I：对本项目日度研究更新，首先需要的是合理分段、限速和错误处理；没有证据表明现在需要额外申请高频额度。全期请求量和单次查询大小限制仍需实测，不能把每分钟额度解释为查询结果覆盖保证。

### 3.2 Transelectrica：优先确认结算出口和正式取数条件

I：目前最重要的是取得明确的数据渠道和字段说明；现有公开 JSON 已有成功样本，尚无依据认定必须新建账户或购买接口。

拟确认内容：

1. 最终逐 QH 缺额/余量偏差价格、系统量的官方历史导出地址、可用起始日、初版/修订/终版标识及发布时间。
2. 容量统计价格和激活边际价格的完整单位、支付规则、产品方向，以及 mFRR scheduled/direct 的价量对应。
3. 官方认可的自动批量出口、访问条件、合理请求频率、分页/区间上限、字段文档和变更通知；当前后台 JSON 路线是否适合持续数据消费。
4. DST 容量越界/缺时段的处理与修订文件；预测的历史发布版本能否获取。

渠道可以是正式 API、CSV/XLSX、文件归档或数据服务。是否需注册/申请/付费属于 U，先根据运营方说明判断，不能预设一定是某种 API。

### 3.3 OPCOM：先确认历史数据服务，暂缓 M7 交易 API

F：OPCOM 当前 M7 API-PI 文件的用途是让市场参与者通过程序接入日内交易系统，并规定费用和访问条件；当前文件适用期为 2026-08-01—2026-12-31 [S06]。

I：当前任务是研究历史数据及定期更新，暂不建议购买该交易接口。上述文件没有证明该接口能补全 2025-01—2026-08 的历史 IDA/成交/盘口、缺值解释或历史发布版本。未来进入真实自动交易或有明确实时盘口需要时，再单独评估参与资格、接口功能与成本。

拟确认内容：完整的 IDA1/2/3 历史价格和成交量导出；本轮空值原因；IDCT 成交时刻/ID/交付区间/买卖记录定义；若有历史盘口数据服务，确认覆盖、字段、下载方式及研究使用许可。这些确认结果可能指向公开文件、授权数据服务或其他收费产品，目前尚不确定。

## 4. 现有取数方式还缺哪些运行能力

F：本轮辅助工具主要按保存的固定日期请求获取样本。`fetch_public.ps1` 会跳过已有获取回执，包括失败回执；失败重试由新的请求 ID 单独执行。该行为满足样本原件不可覆盖要求，但直接重复运行同一请求清单不能刷新原来的数据，也不能自动重新尝试已记录失败的请求。当前没有连续日度运行记录。

I：进入定期获取前，需要另做以下工作，并保留不可覆盖原则：

| 能力 | 向下应做的工作 | 能解决什么 |
|---|---|---|
| 日期与批次 | 按来源时区生成每日新日期/新批次；已采日期的再次抓取也建立新版本 | 从固定样本转为持续增量；保存实际获取时刻 |
| 重试和续传 | 为超时、临时服务器错误和限流做有界重试/退避；逐数据项记录待补队列 | 避免一次失败长期缺失；不重复覆盖原件 |
| 响应验证 | 检查重定向、内容格式、有效数值数、产品方向、单位、分页和范围 | 防止首页 HTML、空模板、截断结果被当成功数据 |
| 日期完整性 | 按原生粒度与来源时区核 23/24/25 小时日；跨来源按 UTC 对齐并取相邻源日 | 防止 DST 假缺值及不同来源日界少一小时 |
| 修订与预测版本 | 重抓历史窗口时保留版本/哈希/获取时间；发布时刻只有有证据才填写；预测和实际分表 | 追踪变化；从现在开始积累可见信息记录，不能恢复此前未留档 vintage |
| 状态与告警 | 分开“请求成功、解析成功、字段完整、版本确认”；汇总缺口和待补原因 | 判断一次定期运行是否真正可用 |
| 交叉核验 | DA 与第二官方来源检查；偏差终价对官方结算；月报只作控制 | 发现价格口径、币种和修订差异 |

本轮 199 次获取尝试与 177 份原件包含多种日期、格式、重试及网页资料，**不能用 177/199 作为服务可用率**；已有 7887 项处理检查 PASS 也不能替代连续运行测试。

## 5. 拟议的定期更新与验收条件（A，未部署）

1. **先连续试运行 14 个自然日。** 对已可用的 DA、系统报表、曲线和研究展示汇率每日运行；月报按月检查。14 日是本项目拟议测试窗口，不是官方保证，且不足以证明跨季度或 DST 稳定性。
2. **发布日期驱动取数。** 每个数据集先确认官方发布时间、延迟和交易/交付日定义，再设获取时点及缺值告警；不把所有市场统一设为同一个“次日即最终”的期限。
3. **保留修订检查。** 可先将近 7 日、近 30 日及尚未确认终版的结算月份纳入重抓候选窗口；这些是 A，待核官方修订周期后调整，不把窗口外数据自动判终版。
4. **统计分数据集结果。** 每日批次必须有回执，任何失败和缺值有待补或说明；核对预期日期/区间与实际有效数值覆盖。对已关闭样本依赖的数据，才讨论扩大取数；偏差终价和 IDA 缺口继续保留阻塞，不由其他成功数据掩盖。
5. **处理新版本。** 原件不覆盖；同日同产品的变化有版本和差异记录。不同币种/时区/产品、月报与原生时序不得混为独立的交叉证明。
6. **通过后再判断长期运行可用性。** 若公共渠道在试运行后仍持续缺失关键字段或无法稳定更新，再按具体缺口申请授权历史服务。14 日运行通过只支持对应试运行范围，不能宣称历史 20 个月和所有市场全部完整。

该安排没有创建自动任务、启动全期下载、申请账号、发送外部邮件或购买服务，也未推进策略、MILP、实现或收益测算阶段。
