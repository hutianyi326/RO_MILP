# 罗马尼亚 aFRR 激活价格 容量报价与三相异常补充研究

本报告回答三个问题：一个完整月的 aFRR 激活收入数据是否能取得；哪里能下载构造容量中标率所需的全部有效报价 MW；50 个不可计算季度和另 1,739 个三相超限季度分别是什么原因。研究日为 2026-10-02，历史诊断范围为 2025-01 至 2026-08，IDA 仍不纳入模型。

结论：已取得并核验 2025 年 8 月完整激活价格和电量样本；本轮没有找到并验证可直接替代西班牙完整容量报价曲线的公开下载源；已将 50 个不可计算季度全部追溯到源空值或源小时缺失。三相超限是将系统激活电量除以已签容量合同量后得到的计算结果；资源池范围不一致是有规则依据的候选解释，其实际贡献比例尚未证实。不能解释为电池真的运行了超过 15 分钟，也不能直接宣布官方电量错误。仍可编写有明确假设的研究 MILP，但不能把这组比例未经处理地作为本站激活时长输入。

F 为官方观察，I 为计算或解释，A 为建模假设，U 为待确认事项。完整来源、访问日期和字段定位见 [范围与证据目录](scope_and_sources.md)。本报告不变更国家状态或旧阶段门禁，不运行优化、收益回测或预测。

### 激活收入可以推进到哪一步

F：所读取的 ANRE 规则合并网页 Art.63 对本地平台能量报价规定 lei/MWh，Art.91–93 支持边际价及支付方向；本轮 API 数值保留原符号。来源 S09。本轮未完成这些条款在整个研究期的后续修订逐条排查，以下现金流仅为有条件的研究代理，不据此批准全期法律或结算最终性。

I：若模型明确采用该公开季度价格作为结算价代理，本站正数上/下调电量分别为 e_up、e_down，则参与者视角候选现金流为：

`cash_RON = price_up × e_up − price_down × e_down`

这里 e 已是 MWh，不再乘 0.25；若输入是激活 MW，必须先乘时长得到 MWh。下调价格为负时可形成收入，为正时形成支出，不能取绝对值或重复翻转符号。换为 EUR 时另登记 RON/EUR 换汇规则。

A/U：公开字段是否是对应结算版本的最终价格、季度内价格的具体聚合方式、系统激活量是否等于结算电量以及本站可分得的激活量，仍不能由这次样本下载推定。数据表因此使用 `price_*_ron_per_mwh_candidate`、`not_site_cash=True` 和显式状态列。不是必须取得真实项目发票后才允许研究，而是应将代理口径写为假设并作敏感性检验。

交付：[整月价量表](afrr_price_energy_sample_202508.csv)、[样本统计及交叉核验](sample_month_summary.json)。这次完成一个新增月，没有将其扩大表述为全期激活价格已齐。

## 容量总报价 MW 的深入搜索结果

西班牙 v2.1 的系统中标系数为 `p = 已分配容量 A / 全部有效报价容量 O`，按交付时段和方向计算。所需 O 包括未中标的有效报价，必须剔除撤回、无效或被后续版本替换的报价，不能将版本重复相加。

| 检查的官方来源 | 本轮实际取得或确认的内容 | 能否直接提供所需 O |
|---|---|---|
| DAMAS II 容量列表及详情 | 需求、满足率、平均接受价、供方合同量；复查 3 场详情；当前公开菜单和页面定义已检查 | 未见总有效报价 MW 或含未中标报价的完整量价块 |
| TSO 官方逐日 `ansTenderResults` Excel | 从官方目录发现附件并下载 5 日，含服务、参与者、BID、DEMANDED POWER、ACCEPTED_POWER、AVERAGE PRICE | 不可以，样本没有原始 offered MW 列，也没有逐小时全部量价曲线 |
| TSO `ANS_bids.xml` | 容量报价报送格式，含日期/数量/参与者占位符 | 不可以，模板不是市场历史数据 |
| ENTSO-E GL EB 12.3.F | 官方定义为已接受报价集合；部分接受时可报告其原始报价量 | 不可以，缺未接受报价；其量甚至不一定等于实际采购量 A |
| ENTSO-E GL EB 12.3.B&C | 平衡能量报价的 MW 与价格 | 不可以替代容量报价 O；可作为进一步研究激活资源池的候选 |
| DAMAS 参与者 WebService 指南 | 说明登录认证及按用户权限执行 | 未证明取得账号就能下载全市场完整报价；未登录、未申请账号 |
| TSO 市场监测流程 §8.1.4 | 2019 年官方流程将逐日逐时的报价量价与合同量分别列为内部监测输入 | 是向 TSO 询问匿名导出的具体线索，不是已验证的公开下载或当前权限承诺 |

### 新发现的 Excel 为什么不能当报价曲线

F：2025-08-15 的 `Sheet 1!A8:I8` 有九个字段，aFRR 上调每个报价行的 DEMANDED POWER 均为 4,800；下调也一样。aFRR Up 的 Grand Total 为 4,800，见 H41；Down 见 H25。BID 列是报价标识，不是报价 MW。

I：4,800 与 `200 MW × 24 个小时` 相符，属于日内小时数量聚合；不是每个参与者报了 4,800 MW。该字段沿参与者行重复，不能逐行求和作为市场供给量。五个样本中 4 个普通日的 aFRR 日中标汇总均与 API 小时汇总一致。存在零或空 ACCEPTED_POWER 的行也不能补出其原始报价数量和价格曲线。

F/I：2025-10-26 Excel 的上下调日中标汇总均为 4,375，而 API 可见 24 个小时合计为 4,200，相差 175，恰好与一个 175 MW 小时相符。这为 DST 当日 API 少一个小时提供第二个官方出口的证据；同机构出口仍不能算独立机构验证。日汇总不足以单独证明缺失小时的原始报价价量，暂不填回旧表。

### 数据申请应具体索取什么

I：最直接的后续对象是 Transelectrica 的容量拍卖/市场监测数据管理方。要求按 2025-01 至 2026-08、产品 FCR/aFRR Up/Down、招标编号和交付 UTC 时段，提供以下两种格式之一：

1. 匿名完整有效报价块：bid_id、version、validity/status、offered_MW、bid_price、accepted_MW、单位、提交/关闭/公布时间及撤回/替换关系；
2. 若不能给完整曲线，提供逐时段 `total_valid_offered_MW` 与 `total_accepted_MW`，并说明聚合、修订和 DST 规则。这已足以构造 p，但不能恢复供给曲线形状。

无需参与者姓名即可完成研究。未向机构发送请求，未注册接口。结论严格为“本轮未找到并验证公开完整报价源”，不是“该数据不存在”或“必须购买商业接口”。ENTSO-E API 账号本身不会把仅接受报价的数据集变成完整报价集合。

A：取得 O 前，可以沿用西班牙 full_fill 的 p=1 基准或人为中标率敏感性，但必须标为外生假设。不得以需求满足率、参与者中标数量占比、能量激活率或日汇总采购量冒充历史容量中标率。

## 1739 个三相比例超限季度

I：严格复用上一轮诊断定义：`alpha_up = E_up/(A_up × 0.25)`，`alpha_down = E_down/(A_down × 0.25)`。E 为系统 MWh；A 为已核验的容量合同 MW；一小时 MW 映射到四个季度时保持 MW 不变。不是把 MW 除以 4 后又乘 0.25。

西班牙三相占时为 `15×alpha_down`、`15×alpha_up`、`15×(1−alpha_up−alpha_down)` 分钟。无激活相仍可能执行基准充放计划，不等于电池功率为零。

### 具体案例与原因判断

F/I：最大案例为当地 2026-02-15 20:15，系统上调电量 111.150 MWh、下调 0；同小时上调合同容量 175 MW，最多对应 `175×0.25=43.75 MWh`。比值为 2.540571，超出 67.400 MWh；111.150 MWh 在 15 分钟内对应平均功率 444.6 MW。原件日请求、招标详情、日中标 Excel 分别复核电量和合同口径，复查值未变。

F：所读取规则版本的 Art.39 允许未签容量合同部分提交平衡能量报价；该版本及后续修订边界见来源 S09。I：在这一机制下，全系统激活电量的资源集合不必等于容量拍卖中标的资源集合；用前者除以后者，不能保证得到处于 0—1 的本站激活比例。该机制为系统量大于合同容量提供有依据的候选解释，但缺乏逐资源激活/报价数据，不能将所有 1,739 个季度的超额逐笔归因于无容量合同资源，也未确定该机制在超限原因中的贡献比例。

I：1,738/1,739=99.94250% 的超限季度是单一方向已超限，故“上下调相位先后顺序”或“两方向同时出现”不是本组超限的主要算术来源。唯一仅合计超限的季度是当地 2025-02-11 17:00，alpha_up=0.06276、alpha_down=0.96722，合计 1.02998。

I：20 个月均有超限，正常月份也存在；最大案例全天合同容量均为 175 MW。源 UTC 时标唯一，且数据转换已用 40 份原始 JSON 独立复算。因此不能用“整体挪动一小时”或“都是 DST”解释全部异常；仍需官方确认个别字段业务聚合和资源范围。

### 如果直接截断会改变多少数据

I，纯诊断：若分别把各方向电量强行压到 `合同 MW × 0.25`，将删除上调 12,094.743 MWh、下调 10,686.389 MWh，分别占同方向有容量匹配且电量非空样本的 3.72593% 和 2.93407%。这仍未解决唯一的合计超限季度。该结果说明截断会改变历史电量，不能叫“修复误差”；也不能把这两个比例当收益损失率。本轮未把截断值写入模型。

## 对罗马尼亚研究模型的处理建议

1. I：一个月样本证明现有公开价格接口可用于进一步全期采集；后续仍需逐月核完整性与正负号。报价总量与激活参数是另外两个独立问题。
2. A：容量收益可保留 p=1 或明确的外生敏感性情景；没有总报价量时不生成“历史中标率”。p 仅折减容量收入的口径若沿用西班牙，应保留全额物理预留并披露其局限。
3. I：三相形式本身可以沿用，当前用 `全系统激活量/合同容量` 得出的系数不能无条件沿用。优先寻找容量中标资源对应激活量，或与激活量覆盖一致的可用能量报价资源池及高频/分段响应信息。
4. A/U：即便拿到总能量报价 MW，也不能自动保证单站三相的上下调比例和小于 1；必须重新检验同一资源的上下调关系。若采用外生三相场景，应列明校准方法、0≤alpha 和合计≤1、缺失与超限处理，禁止以强制归一化冒充实测参数。
5. A：如仅排除异常季度进行条件样本测算，需输出被排除时段、完整订单边界和样本选择偏差；不得删除已冻结的非零承诺或跨空档重置 SOC。该建议不在本轮实施。
